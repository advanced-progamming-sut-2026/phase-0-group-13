PvZ Skin, field notes for your own project

A working reference for pulling pizpizi/pvz-skin into a LibGDX game: how to install it, how the two classes it exposes behave, and every button, label, font, and nine-patch it ships — rendered from an actual local build, not the README's screenshots.

v0.1.1 JDK 8+ LibGDX 1.12.1+ TenPatch 5.2.3+ MIT license
How this was verified: the repository was cloned, built with gradlew.bat generatePreviews, and every image in the catalog below is a direct, unedited output of that build — not a reproduction of the GitHub README's assets.

Overview

pvz-skin is a Scene2D Skin for LibGDX, built from a texture atlas and font set extracted from Plants vs. Zombies 2 and exported with Skin Composer. It gives you themed TextButton, ImageButton, Label, ProgressBar, CheckBox, and Slider styles, ten bitmap/FreeType fonts, and a set of TenPatch nine-patch drawables for panel and dialog backgrounds — plus one custom widget, BorderedTable.

Everything the skin needs — the atlas PNG, the .atlas/.json pair, and six TTF font files — is bundled as classpath resources inside the published jar. There is nothing to copy into your own assets/ folder; you add two Gradle dependencies and call one method.

It is a library, not a runnable app: the only executable entry point in the repo is a preview generator (SkinPreviewGenerator) used to produce the catalog images below, not something your game depends on.

TenPatch is a hard requirement, not an optional extra — the skin JSON references TenPatchDrawable directly for every panel background, so the skin will fail to load without it on the classpath.

Install

Add JitPack as a repository, then declare pvz-skin and TenPatch. In a multi-module LibGDX project, put this in your core module so every platform target sees it.

core/build.gradle · Groovy DSL
// repositories
repositories {
    mavenCentral()
    maven { url 'https://jitpack.io' }
}

// dependencies
dependencies {
    api "com.github.pizpizi:pvz-skin:v0.1.1"
    api "com.github.raeleus.TenPatch:tenpatch:5.2.3"
}
core/build.gradle.kts · Kotlin DSL
repositories {
    mavenCentral()
    maven("https://jitpack.io")
}

dependencies {
    api("com.github.pizpizi:pvz-skin:v0.1.1")
    api("com.github.raeleus.TenPatch:tenpatch:5.2.3")
}
pom.xml · Maven
<repositories>
    <repository>
        <id>jitpack.io</id>

    </repository>
</repositories>

<dependencies>

    <dependency>
        <groupId>com.github.raeleus.TenPatch</groupId>
        <artifactId>tenpatch</artifactId>
        <version>5.2.3</version>
    </dependency>
</dependencies>
Your launcher module still needs the usual LibGDX natives — gdx-backend-lwjgl3, gdx-platform:natives-desktop, and gdx-freetype-platform:natives-desktop (or your target platform's equivalents). pvz-skin exposes gdx and gdx-freetype as api, so the classes resolve everywhere, but native libraries are always declared per-platform in your own launcher module — that part is unrelated to this skin.

Quick start

A minimal, complete ApplicationAdapter that loads the skin and lays out a title, a button, and an XP bar. This compiles as-is against the dependencies above.

package com.example.game;

import com.badlogic.gdx.ApplicationAdapter;
import com.badlogic.gdx.Gdx;
import com.badlogic.gdx.scenes.scene2d.InputEvent;
import com.badlogic.gdx.scenes.scene2d.Stage;
import com.badlogic.gdx.scenes.scene2d.ui.*;
import com.badlogic.gdx.scenes.scene2d.utils.ClickListener;
import com.badlogic.gdx.utils.ScreenUtils;
import com.badlogic.gdx.utils.viewport.ScreenViewport;
import pvz.skin.PvzSkin;

public class MyGame extends ApplicationAdapter {
    private Stage stage;

    @Override
    public void create() {
        // PvzSkin.get() uploads a texture atlas, so it needs a live GL context.
        // Call it from create() (or later) -- never from a static field or a constructor
        // that runs before Lwjgl3Application starts.
        Skin skin = PvzSkin.get();

        stage = new Stage(new ScreenViewport());
        Gdx.input.setInputProcessor(stage);

        Table root = new Table();
        root.setFillParent(true);
        stage.addActor(root);

        Label title = new Label("Choose Your Plants", skin, "big_outline");

        TextButton play = new TextButton("Play", skin, "green");
        play.addListener(new ClickListener() {
            @Override
            public void clicked(InputEvent event, float x, float y) {
                Gdx.app.log("MyGame", "Play pressed");
            }
        });

        ProgressBar xp = new ProgressBar(0, 100, 1, false, skin, "xp_green");
        xp.setValue(72);

        root.add(title).padBottom(30).row();
        root.add(play).size(200, 70).padBottom(20).row();
        root.add(xp).width(260);
    }

    @Override
    public void render() {
        ScreenUtils.clear(0.09f, 0.11f, 0.08f, 1f);
        stage.act();
        stage.draw();
    }

    @Override
    public void resize(int width, int height) {
        stage.getViewport().update(width, height, true);
    }

    @Override
    public void dispose() {
        stage.dispose();
        // PvzSkin caches a single process-wide Skin instance. Dispose it once, at final
        // application shutdown -- not per-screen -- since PvzSkin.get() never reloads
        // after the first call, disposed or not.
    }
}

Core API

Three classes, all in package pvz.skin. This is the entire public surface of the library.

final classPvzSkin

A lazily-initialized, process-wide singleton wrapping the bundled skin.

public static Skin get()

First call constructs a FreeTypeSkin from Gdx.files.classpath("skin/pvz2_skin.json") and caches it in a static field; every later call returns the same instance. There is no way to force a reload short of restarting the process.

classFreeTypeSkin extends Skin

What makes fonts work at all. A stock Skin can't deserialize the FreeTypeFontGenerator blocks a Skin Composer export embeds — it has no no-arg constructor for the JSON reader to call. This subclass registers a custom serializer that reads the block, generates a BitmapFont from the matching bundled .ttf, and adds it to the skin under that block's name.

PvzSkin uses this internally, so you won't normally touch it directly. It's public because it's independently useful: reuse it if you load your own Skin Composer export that also embeds FreeType font blocks.

Skin skin = new FreeTypeSkin(Gdx.files.internal("myskin/myskin.json"));

classBorderedTable extends Table

A Table pre-decorated with the dialog border and inner panel background, both drawn as TenPatch nine-patches so they scale to any size. The constructor already calls pad(50) and pulls both drawables from PvzSkin.get() — just add children like a normal table.

BorderedTable dialog = new BorderedTable();
dialog.add(new Label("Level Complete!", skin, "big")).padBottom(10).row();
dialog.add(new TextButton("Continue", skin, "green"));
dialog.pack();
dialog.setPosition(
    (stage.getWidth() - dialog.getWidth()) / 2f,
    (stage.getHeight() - dialog.getHeight()) / 2f
);
stage.addActor(dialog);

If your content looks oddly inset, that's the baked-in pad(50) — call dialog.pad(...) afterward to override it.

Recipes

Combined, runnable patterns beyond the single-widget quick start — a HUD, a confirmation dialog, a raw TenPatch background, and event listeners. All assume the same imports as Quick start, plus com.badlogic.gdx.scenes.scene2d.utils.ChangeListener where noted.

HUD row: image button + progress bar + label

Table hud = new Table();

hud.top().left().pad(10);

Confirmation dialog with BorderedTable

BorderedTable confirm = new BorderedTable();
confirm.add(new Label("Quit to main menu?", skin, "medium")).colspan(2).padBottom(16).row();

TextButton no  = new TextButton("No", skin, "brown");
TextButton yes = new TextButton("Yes", skin, "green_small");
yes.addListener(new ClickListener() {
    @Override
    public void clicked(InputEvent event, float x, float y) {
        confirm.remove();
        // e.g. game.setScreen(new MainMenuScreen(game));
    }
});

confirm.add(no).size(120, 50).padRight(10);
confirm.add(yes).size(120, 50);

confirm.pack();
confirm.setPosition(
    (stage.getWidth()  - confirm.getWidth())  / 2f,
    (stage.getHeight() - confirm.getHeight()) / 2f
);
stage.addActor(confirm);

A TenPatch drawable as a plain panel background

You don't need BorderedTable to use the nine-patches — any Table or Window takes one directly as a background and it scales cleanly to whatever size you give the table.

Drawable panelBg = skin.getDrawable("image_ui_mainmenu_mm_settings_tab_10");

Table settingsPanel = new Table();
settingsPanel.setBackground(panelBg);
settingsPanel.pad(20);
settingsPanel.add(new Label("Settings", skin, "big"));

Listening to CheckBox and Slider changes

final CheckBox muteMusic = new CheckBox(" Mute Music", skin, "default");
muteMusic.addListener(new ChangeListener() {
    @Override
    public void changed(ChangeEvent event, Actor actor) {
        audio.setMusicEnabled(!muteMusic.isChecked());
    }
});

final Slider volume = new Slider(0, 1, 0.05f, false, skin, "default-horizontal");
volume.setValue(0.8f);
volume.addListener(new ChangeListener() {
    @Override
    public void changed(ChangeEvent event, Actor actor) {
        audio.setMusicVolume(volume.getValue());
    }
});

Troubleshooting

Everything below was hit and confirmed while building this guide, except where noted as a standard LibGDX gotcha.

SSLException: trustAnchors parameter must be non-empty

Thrown by gradlew itself while downloading the Gradle distribution, before your build even starts. Caused by JAVA_HOME pointing at a JDK with a broken or empty cacerts truststore — a stray old/portable JDK install is a common cause.

Fix: point JAVA_HOME at a real, current JDK before invoking the wrapper.

:: Windows cmd
set JAVA_HOME=C:\path\to\jdk-17
gradlew.bat generatePreviews
Gradle wrapper needs JDK 17+ even though this library targets JDK 8

Two different Java versions are in play: the one that runs Gradle itself (this repo's wrapper pulls Gradle 9, which needs a modern JDK to launch) versus sourceCompatibility/targetCompatibility in build.gradle, which control what bytecode the library compiles to (8). They don't have to match.

Crash or black screen calling PvzSkin.get()

Loading the skin uploads a texture atlas to the GPU, which needs a live GL context. Calling PvzSkin.get() from a static field initializer, a constructor, or anywhere before Lwjgl3Application (or your platform's backend) has started will fail. Call it from create() or later.

NoClassDefFoundError: com.ray3k.tenpatch.TenPatchDrawable

TenPatch didn't resolve onto the runtime classpath. pvz-skin declares it as an api dependency, which usually pulls it through transitively — but Gradle still needs https://jitpack.io declared as a repository in your own project for that resolution to succeed.

UnsatisfiedLinkError / blank window on desktop (standard LibGDX, not specific to this skin)

Your launcher module is missing native libraries. It needs gdx-backend-lwjgl3, gdx-platform:...:natives-desktop, and gdx-freetype-platform:...:natives-desktop (this skin uses FreeType fonts, so the freetype natives specifically are easy to forget).

previews/ folder is missing after running generatePreviews

It's written relative to Gradle's working directory — the repo root — not any particular module folder. Look next to build.gradle.

License & provenance

MIT-licensed. The README states it's an unofficial, fan-made project, not affiliated with PopCap Games or Electronic Arts, and that "no game assets are distributed with this skin."

Worth knowing before you redistribute: that last claim doesn't match what's actually in the repository. src/main/resources/skin/ is tracked in git and ships inside the published jar, and it contains a full extracted texture atlas (pvz2_skin.png, ~2.9 MB) plus six .TTF font files — i.e. real game assets, not placeholders. This is a factual observation about the repo's contents, not legal advice; if you plan to ship a product built on this skin, that's worth your own legal review rather than taking the README's disclaimer at face value.

libPVZ, field notes for your own project

A working reference for pulling pizpizi/libPVZ into a LibGDX game: the asset layout it expects, how TextureBank and PamPlayer fit together, every public class and method, and the gotchas found by actually reading the source.

v0.1.4 JDK 8+ LibGDX 1.12.1+ MIT license
How this was verified: the repository was cloned at tag v0.1.4 and compiled locally (gradlew.bat compileJava compileTestJava) — that part succeeded. The bundled demo needs your own extracted Plants vs. Zombies 2 assets to actually render anything, which weren't available in this environment, so the demo itself was read (not run) to write this guide. Every code claim below traces back to a specific line in src/main/java.

Overview

libPVZ is a LibGDX runtime for PopCap's PAM animation format — the skeletal/vector animation system Plants vs. Zombies 2 uses for every plant, zombie, and effect. It does not ship any game data itself; you point it at your own extracted assets and it parses the binary .PAM files, bakes the hierarchy into flat per-frame quad arrays, and draws them through a normal Batch.

Two classes carry the whole system: TextureBank resolves image/atlas IDs to actual Texture objects from your extracted resources.json, and PamPlayer is a stateless renderer that reads and bakes .PAM files on a background thread and draws them by path+clip or by a cached ClipRef handle.

Unlike a texture atlas library, there's no way to discover valid PAM paths, clip names, or resource IDs from the API itself — you either read the extracted resources.json by hand or use the companion PvZ Asset Browser tool the author built for exactly this.

You also need a full extracted copy of Plants vs. Zombies 2's assets on disk. libPVZ ships zero game data — nothing to add, nothing to license-check on the library's side; the obligation is entirely on how you sourced your own assets.

Asset layout libPVZ expects

This is the single most important prerequisite — both constructors below fail immediately if the folder doesn't look like this.

<assets folder>/
├── resources.json          (or RESOURCES.json)   ← required by TextureBank
├── atlases/                (or ATLASES/)        ← required by TextureBank, holds the atlas .png files
└── pam/                    (or IMAGES/)         ← required by PamPlayer, holds the .PAM files

Each pair is a fallback, checked in that order (lower-case first, then the fully-capitalized variant) — that's TextureBank and PamPlayer's constructors probing for both the raw game extraction layout (usually upper-case) and a manually-renamed one. Note this fallback is a single fixed check, not a case-insensitive search: on a case-sensitive filesystem (Linux/macOS), a folder named e.g. Atlases matches neither and will fail.

The two fallbacks are independent. You can end up with resources.json lower-case but ATLASES/ upper-case, if that's how your extraction tool produced them — each constructor checks its own pair, not a consistent casing across the whole folder.

PAM paths passed to PamPlayer (e.g. player.draw(batch, "ZOMBIES/PEASANT/PEASANT.PAM", ...)) are relative to whichever of pam/ or IMAGES/ was found — so that path really resolves to <assets>/pam/ZOMBIES/PEASANT/PEASANT.PAM (or the IMAGES/ equivalent).

TextureBank's resolution constructor argument (e.g. "768") must match a "res" value used inside the groups of your resources.json — it's how the library picks the right variant when the same image exists at multiple resolutions. Groups with no "res" tag at all are always kept as a fallback (score 1), so an unmatched resolution silently falls back to those rather than failing outright.

Architecture

Two independent systems that share the same background-loading pattern: TextureBank resolves images/atlases, PamPlayer resolves and bakes animation files. PamPlayer asks TextureBank for the atlases a given animation needs, but never touches raw PNGs itself.

Everything the worker thread produces is only ever handed off to the GL thread through Gdx.app.postRunnable, so PamPlayer's public methods are safe to call from render() without extra synchronization on your end — but that also means a freshly-referenced animation renders nothing for a few frames while it loads. See Recipes for preloading it away.

Install

build.gradle · Groovy DSL
repositories {
    mavenCentral()
    maven { url 'https://jitpack.io' }
}

dependencies {
    api "com.github.pizpizi:libPVZ:v0.1.4"
}

That's the entire dependency graph — libPVZ only depends on core gdx (declared api in its own build, so it flows through to you automatically). No TenPatch, no FreeType, nothing extra to add for the library itself.

Your launcher module still needs LibGDX's usual desktop natives — gdx-backend-lwjgl3 and gdx-platform:...:natives-desktop (or your target platform's equivalents). That's standard LibGDX setup, unrelated to this library.

Quick start

Trimmed from the repo's own Demo.java (src/test/java/pvz/demo/Demo.java) down to the essentials: load one animation, play its first clip, loop forever.

package com.example.game;

import com.badlogic.gdx.ApplicationAdapter;
import com.badlogic.gdx.Gdx;
import com.badlogic.gdx.files.FileHandle;
import com.badlogic.gdx.graphics.OrthographicCamera;
import com.badlogic.gdx.graphics.g2d.SpriteBatch;
import com.badlogic.gdx.utils.ScreenUtils;
import pvz.libpvz.pam.ClipRef;
import pvz.libpvz.pam.PamPlayer;
import pvz.libpvz.textures.TextureBank;

public class MyGame extends ApplicationAdapter {
    private static final String PAM = "ZOMBIES/PEASANT/PEASANT.PAM";

    private TextureBank textures;
    private PamPlayer player;
    private SpriteBatch batch;
    private OrthographicCamera camera;
    private ClipRef idle;
    private float stateTime;

    @Override
    public void create() {
        batch = new SpriteBatch();
        camera = new OrthographicCamera(1280, 720);
        camera.position.set(0, 0, 0);
        camera.update();

        FileHandle assets = Gdx.files.absolute("/path/to/Base Assets");
        textures = new TextureBank("768", assets);
        player = new PamPlayer(textures, assets);

        // Blocks until the .PAM and its atlases are parsed and uploaded --
        // fine at load time, avoid it inside render().
        player.loadSync(PAM);
        idle = player.getClip(PAM, "idle");
    }

    @Override
    public void render() {
        stateTime += Gdx.graphics.getDeltaTime();
        ScreenUtils.clear(0.1f, 0.1f, 0.1f, 1f);

        // Required every frame: drains TextureBank's AssetManager queue.
        textures.update();

        batch.setProjectionMatrix(camera.combined);
        batch.begin();
        player.draw(batch, idle, stateTime, 0, 0, true);
        batch.end();
    }

    @Override
    public void dispose() {
        batch.dispose();
        textures.dispose();
    }
}

To run the repo's own interactive demo instead of writing your own: set -Dpvz.assets=/path/to/Base Assets (and optionally -Dpvz.pam=...) and run gradlew.bat runDemo from the repo root — see Troubleshooting for the JDK caveat that applies to the wrapper itself.

Core API

Five public classes across two packages: pvz.libpvz and pvz.libpvz.{pam,textures}. PamData, PamBinaryReader, and BakedAnimation are package-private — internal, not part of the API surface.

TextureBank implements Disposable

Owns an internal AssetManager and resolves image/atlas resource IDs (strings from resources.json) into loaded LibGDX Texture/TextureRegion objects.

TextureBank(String resolution, FileHandle assetsFolder)
TextureRegion region(String imageResourceId) — a sub-rect of its atlas; loads+caches the atlas synchronously on first call
TextureRegion atlas(String atlasId) — the whole atlas texture, e.g. for debugging
void loadSync(String atlasId) / void loadAsync(String atlasId, Runnable cb)
void update() — drains the AssetManager queue; call every frame, unconditionally
void unloadAtlas(String atlasId) — disposes one atlas texture and its cached regions
FileHandle atlasFile(String atlasId) — the resolved .png FileHandle on disk
int exportAtlasParts(String atlasId, FileHandle outDir) — slices every image in an atlas out to individual PNGs
int exportImage(String imageId, FileHandle outDir) — see the caveat in Troubleshooting
ResourceIndex getResourceIndex() — same as resourceIndex(), both exist
int loadedTextureCount()

Resolution loading is lazy: nothing is fetched until the first region()/atlas()/loadSync/loadAsync call for that atlas. region() and the plain atlas() call block synchronously the first time; use loadAsync ahead of time if you want to avoid a hitch.

PamPlayer

Stateless per-call renderer with an internal cache. One instance can draw the same or different animations at as many positions as you want — nothing about a draw call mutates shared state other than the load caches.

PamPlayer(TextureBank textures, FileHandle assetsFolder)
void draw(Batch, String pam, String clip, float time, float x, float y, boolean loop)
void draw(..., Map<String,Boolean> partsVisibility) — overload with per-part show/hide
void drawPart(Batch, String pam, String clip, float time, float x, float y, String part) — draws only that named part (and its descendants); always loops regardless of the caller
ClipRef getClip(String pam, String clip) — null until the animation has finished baking; poll or use loadAsync's callback
void draw(Batch, ClipRef, float time, float x, float y, boolean loop[, Map<String,Boolean>]) — the fast path, no string lookups at all
List<String> clips(String pam) — loads synchronously if not cached yet
Rectangle bounds(String pam[, String clip]) — local-space bounding box, loads synchronously
float clipDurationSeconds(String pam, String clip)
void loadSync(String pam) — blocks the calling thread until parsed, baked, and textures uploaded
void loadAsync(String pam, Runnable onLoaded) — callback fires on the GL thread

Every draw(...) overload silently no-ops (draws nothing, throws nothing) if the animation hasn't finished loading yet. That's bakedAsync's contract: it triggers a background load and returns immediately.

ClipRef final

An opaque handle returned by getClip(...). Its only public member is duration (the clip's length in seconds, precomputed as frameCount / frameRate) — useful for detecting when a non-looping clip has finished, exactly as the demo does. Obtain it once (ideally at load time) and reuse it every frame instead of calling draw(Batch, String, String, ...) in a hot loop.

ResourceIndex

Parses resources.json once, at TextureBank construction. Get it via textures.getResourceIndex().

ImageEntry image(String id) — fields: id, atlasId, path, ax, ay, aw, ah (atlas-space pixel rect)
AtlasEntry atlas(String id) — fields: id, path, width, height
boolean isAnimationAtlas(String atlasId) — true if any PopAnim resource shares this atlas's parent group
Set<String> imageIds() / Set<String> atlasIds()
List<String> getImagesForAtlas(String atlasId)
String preferredResolution() / int imageCount() / int atlasCount()

When the same resource ID appears in multiple resolution groups, the one matching your requested resolution wins; if none match, the highest-scoring untagged group is used instead of failing.

AtlasLocator · Matrix2D

AtlasLocator is constructed internally by TextureBank (you'll rarely touch it directly) — it scans the atlases folder once and maps each PNG's base filename to its FileHandle, case-insensitively. Its constructor throws IllegalArgumentException immediately if the folder doesn't exist, which is usually the very first error you'll see from a misconfigured asset path.

Matrix2D is a plain 2D affine transform (a, b, c, d, tx, ty, all public fields) used internally to bake the PAM hierarchy. It's public but there's normally no reason to construct one yourself.

Visibility & flags

Some parts are hidden by default based on their name, not an explicit flag in the file. A part's name is checked once at bake time against these rules (from BakedAnimation.Part):

Name matchHidden unless whitelisted
equals "butter"yes
equals "ink"yes
contains "armor"yes
contains "custom"yes
equals "ground_swatch"yes
equals "ground_swatch_plane"yes
contains "arm_outer_upper_bone"yes

The README documents the first five; the arm-bone rule isn't mentioned there but is real (BakedAnimation.Part.computeFlags). To reveal a hidden part, put its exact name in the visibility map passed to draw(...) with value true — the map only needs entries for parts you want to override — everything else follows its default.

Recipes

Preload during a loading screen, draw with ClipRef in gameplay

// Loading screen -- fine to block here
player.loadSync("ZOMBIES/PEASANT/PEASANT.PAM");
ClipRef walk = player.getClip("ZOMBIES/PEASANT/PEASANT.PAM", "walk");

// render() -- zero string lookups per frame
player.draw(batch, walk, stateTime, x, y, true);

Stream in an animation without a loading-screen stall

player.loadAsync("ZOMBIES/PEASANT/PEASANT.PAM", () -> {
    zombieClip = player.getClip("ZOMBIES/PEASANT/PEASANT.PAM", "walk");
});
// until the callback fires, draw(batch, "ZOMBIES/...", "walk", ...) is a
// safe no-op -- nothing is drawn, nothing throws.

Show armor for one instance, butter for another

Map<String, Boolean> armored = new HashMap<>();
armored.put("_zombie_egypt_armor2_states", true);
armored.put("zombie_armor_bucket_norm", true);

Map<String, Boolean> buttered = new HashMap<>();
buttered.put("butter", true);

player.draw(batch, clipRef, stateTime, 0, -200, true, armored);
player.draw(batch, clipRef, stateTime, 0,  200, true, buttered);

Frame a clip with a camera, using its real bounding box

Rectangle bounds = player.bounds("ZOMBIES/PEASANT/PEASANT.PAM", "idle");
// bounds is centered on the animation's local origin -- offset by
// your draw position (x, y) to get world-space framing.
camera.position.set(x + bounds.x + bounds.width / 2f, y + bounds.y + bounds.height / 2f, 0);

Dump an atlas to individual PNGs for inspection

ResourceIndex index = textures.getResourceIndex();
int exported = textures.exportAtlasParts("ATLAS_ZOMBIE_EGYPT_BASIC", Gdx.files.local("debug-export"));
Gdx.app.log("MyGame", exported + " images written");

Prefer this over exportImage(String, FileHandle) for a single image too — see the known bug in Troubleshooting.

Play a one-shot clip, then fall back to idle

ClipRef.duration is exactly what makes this cheap — no need to ask PamPlayer anything mid-animation.

ClipRef idle, attack;
boolean attacking = false;
float stateTime = 0f;

// on the attack trigger:
attacking = true;
stateTime = 0f;

// render():
stateTime += Gdx.graphics.getDeltaTime();
ClipRef current = attacking ? attack : idle;
// don't loop the attack -- we want it to reach its last frame and stop there
player.draw(batch, current, stateTime, x, y, !attacking);

if (attacking && stateTime >= attack.duration) {
    attacking = false;
    stateTime = 0f;
}

Render a single part in isolation (e.g. a UI portrait)

// Draws only the "head" node and anything parented under it -- everything
// else in the hierarchy is skipped. Note drawPart always loops internally
// regardless of what you'd normally pass, so a free-running stateTime is fine.
player.drawPart(batch, "ZOMBIES/PEASANT/PEASANT.PAM", "idle", stateTime, iconX, iconY, "head");

Draw a plain icon straight from the atlas, no PAM involved

For HUD art that's a static image rather than an animation — TextureBank works standalone here, PamPlayer isn't involved at all.

TextureRegion coinIcon = textures.region("IMAGE_REWARD_COIN_SILVER");
if (coinIcon != null) {
    batch.draw(coinIcon, hudX, hudY);
}

Load a whole roster before revealing the level-select screen

List<String> roster = Arrays.asList(
    "ZOMBIES/PEASANT/PEASANT.PAM",
    "ZOMBIES/CONEHEAD/CONEHEAD.PAM",
    "ZOMBIES/BUCKETHEAD/BUCKETHEAD.PAM"
);
AtomicInteger remaining = new AtomicInteger(roster.size());
boolean[] ready = { false };

for (String pam : roster) {
    player.loadAsync(pam, () -> {
        if (remaining.decrementAndGet() == 0) {
            ready[0] = true; // safe to flip to the level-select screen now
        }
    });
}

Free memory when leaving a level

TextureBank.unloadAtlas(...) is the only eviction hook in the library. PamPlayer caches parsed/baked PAMs (animationByPath, bakedByPath) in private fields with no public eviction method at all — the only way to release that memory is to stop referencing the PamPlayer instance itself (e.g. create a fresh one per level) and let it be garbage collected.

// Drops one atlas's Texture and its cached regions immediately.
textures.unloadAtlas("ATLAS_ZOMBIE_EGYPT_BASIC");

// To also drop parsed/baked PAM data, discard the PamPlayer itself --
// there's no unload(pam) equivalent on that side.
player = new PamPlayer(textures, assetsFolder);

Troubleshooting

Confirmed by reading the source or reproducing directly, except where marked as a standard LibGDX/Gradle issue.

exportImage(id, dir) always returns 0

Real bug, reproduced by reading the source. TextureBank.exportImage filters its loop with if (image != imageId) continue; — a reference comparison on String, not .equals(...). The loop variable comes from resourceIndex.imageIds() (fresh strings parsed out of JSON); the imageId you pass in is essentially never the same object instance, so the condition is true on every iteration and nothing gets written.

Workaround: use exportAtlasParts(atlasId, outDir) instead and pick the one file you need out of the output directory — it uses a correct .equals() comparison internally.

IllegalArgumentException: ATLASES directory not found

Thrown by AtlasLocator's constructor — neither atlases/ nor ATLASES/ exists directly under the folder you passed to TextureBank. Double-check you're pointing at the root of your extracted assets, not a subfolder, and check case if you're on Linux/macOS (see Asset layout).

Nothing draws, no exception at all

Two common causes, both silent by design: (1) the animation is still on its background load — every draw(...) overload no-ops until baking finishes; (2) you forgot to call textures.update() every frame, so the atlas texture never finishes uploading even after the PAM itself is parsed and baked.

IllegalArgumentException: Unknown clip 'x'; available clips: [...]

Not really a bug — BakedAnimation.range(...) throws this deliberately, and it lists every valid clip name for that PAM in the message itself. Usually means a typo, or you assumed a clip existed that this particular character doesn't have.

IllegalArgumentException: Not a PAM file (magic 0x...)

PamBinaryReader checks a fixed magic number (0xBAF01954) as the first 4 bytes. This means the path resolved to something that isn't a .PAM file at all — often a sign the pam/IMAGES path was built wrong (see Asset layout) and you're reading an unrelated file.

IllegalArgumentException: Unsupported PAM version

The reader caps out at version 6 (PamBinaryReader.MAX_VERSION). Assets pulled from a much newer game build than this library was written against could exceed that.

SSLException: trustAnchors parameter must be non-empty (environment, not this repo)

Same root cause as pvz-skin's field guide: gradlew.bat needs a JDK with an intact cacerts truststore to download Gradle 9 in the first place. If JAVA_HOME points at a broken/portable JDK, point it at a real one first:

:: Windows cmd
set JAVA_HOME=C:\path\to\jdk-17
gradlew.bat compileJava
